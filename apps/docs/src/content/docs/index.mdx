## The shape of it

```txt
Browser (site + SDK)          Index / Relay              Phone (Identizen app)
        │ 1. discover phone          │                            │
        │ 2. challenge {rp_id, nonce, code, acr, reason?} ── push ─►│
        │                            │        3. site name, code,  │
        │                            │           Face ID           │
        │◄─────── signed assertion ──┼────────────────────────────┤
        │ 4. index verifies; OIDC provider issues id_token         │
```

The site domain is inside the signed challenge, so a phished login on a lookalike domain produces a signature the real site will never accept. The index stores public keys, push tokens, revocation state, and audit events; there is nothing in it an attacker can log in with.
